# Gate proofs

A gate counts only once it has been made to go red by reintroducing the defect it claims to catch. This file records the mutation, the exact failure it produced, and the bound the gate carries in its own header. Newest first.

Auditing a gate means reaching what was measured at the time, never the sentence the gate carries about itself: a gate and its claim can be wrong together and look exactly like a gate that is right.

Every entry names the tree its numbers were taken on. The entries below were all taken on the uncommitted foundation tree of 2026-09-08, before the first commit, so they name files rather than revisions; the first commit carries the same files.

## shot: a page may not carry fewer colour hooks than its census says (`tools/shot.js`, `HOOK_CENSUS` + `auditColourHooks`)

Taken on the uncommitted round tree of 2026-09-19 — `main` at `f5bd0e9` plus the second book's round. All captures named below are under the ignored `out/gatefix/`.

- **The gap, found by review (2026-09-19).** The check enforced that a page which must carry a hook carried **at least one** element with it: `for (const el of els)` plus `if (hook.required && !els.length)`. A chapter with one marked year of four, or a glossary tagging two head-words of fifteen, read as clean — the round's own chapter-1 bug one size smaller. `HOOK_CENSUS` carried the counts (ch01 6 `data-state` + 2 `data-date`; ch02 18 `data-state` = 3 in markup + 15 from the glossary, 4 `data-date`, 7 `data-note`; ch03 1 + 1) and only presence was enforced.
- Claim now, in the tool's header and in the table: every hook carries a FLOOR and the check fails `found < floor`, so a mark added is free and a mark lost is not. Each floor is the census, margin zero, with a `where` saying what its marks are; the numbers were measured on the RENDERED DOM on 2026-09-19 at all three viewports of the gate (`out/gatefix/census.mjs`, 9 loads, identical at 390, 1024 and 1440 px) and each equals what the page's own sources declare — the `data-*` attributes in the chapter's `index.html` plus the `state:` fields in its `glossary.js`, which `src/components/term.js` tags onto the `dt` it builds. A margin of one would let a single silent loss through, which is the defect; a deliberate removal lowers the number in the same commit, and the failure says so. A hook with no floor, or one the check cannot read as an attribute test, fails the run rather than falling back to presence. Every load prints the counts it compared (`census state=zhi 6/6 …`), so a clean line cannot be a count that was never taken.
- **Mutation 1, one mark off a six-mark hook.** `SHOT_PAGES=tongjian/ch02 SHOT_VIEWPORTS=desktop SHOT_THEMES=light SHOT_MUTATE_HOOK='[data-state="zhi"]|0' node tools/shot.js`, with this scratch line at the gate's wait point (straight after `figures = await openPage(…)`, removed again after the capture):
  ```js
  if (process.env.SHOT_MUTATE_HOOK) {
    const [mSel, mNth] = process.env.SHOT_MUTATE_HOOK.split('|');
    const gone = await page.evaluate(({ sel, nth }) => {
      const el = [...document.querySelectorAll(sel)].filter((e) => e.closest('.zj'))[Number(nth) || 0];
      if (!el) return false;
      el.removeAttribute(sel.replace(/^\[\s*([a-z0-9-]+).*$/, '$1'));
      return true;
    }, { sel: mSel, nth: mNth });
    if (!gone) problems.push(`SHOT_MUTATE_HOOK=${process.env.SHOT_MUTATE_HOOK} matched nothing, so the mutation proved nothing`);
  }
  ```
  It removes the `data-state` attribute from the first of the six 智 glossary head-words, so the count drops by one without reaching zero. Failure, exit 1, **one** problem and nothing else (`out/gatefix/mutation-floor-red.txt`):
  > FAIL tongjian/ch02 desktop light (4141 ms)
  >   tongjian/ch02 desktop: the colour hook [data-state="zhi"] is on 5 element(s) here, where this page's census says at least 6 — chapter 2 names the houses in its 世系 paragraphs and tags fifteen glossary head-words from glossary.js, and marks the years and the textual notes in 背景 and 原文 — so 1 of the mark(s) this page carries are gone. A hook that is not there paints nothing, and a hook that is there fewer times than the census says is the same defect one size smaller: the missing marks are invisible to every other check in this file. What would satisfy this: put the mark back on the element that lost it, or, if the removal is deliberate, lower this hook's floor in HOOK_CENSUS in tools/shot.js in the same commit — that table is this page's record of the marks it carries.
- **Mutation 2, one mark off a two-mark hook** — the smallest floor in the table: `SHOT_MUTATE_HOOK='[data-state="wei"]|0'` over `tongjian/ch01`. Same shape, exit 1, `the colour hook [data-state="wei"] is on 1 element(s) here, where this page's census says at least 2 …`; again one problem and nothing else (`out/gatefix/mutation-floor-red-small.txt`).
- **Reverted and green.** `SHOT_PAGES=tongjian/ch01,tongjian/ch02,tongjian/ch03 SHOT_VIEWPORTS=desktop SHOT_THEMES=light node tools/shot.js` → `shot: 3 page loads clean`, exit 0, with the counts on every line: `census date 2/2, state=wei 2/2, state=zhao 2/2, state=han 2/2` (ch01), `census date 4/4, note=textual 7/7, state=wei 3/3, state=zhao 7/7, state=han 2/2, state=zhi 6/6` (ch02), `census note=textual 1/1, state=zhi 1/1` (ch03) — `out/gatefix/green-after-floors.txt`. Re-run after another worker's font-census block landed in the same file: ch01 and ch03 clean, ch02's only failures are that block's own SimSun coverage findings (`out/gatefix/green-after-floors-with-fontblock.txt`).
- **A floor below the count it guards is the same defect, and this one was caught and raised while this entry was being written.** Chapter 2's `[data-date]` floor read **4** in `HOOK_CENSUS` while the shipped page carries **6** — `census date 4/4` is what the floors' own green run recorded on the tree of that moment, and six `data-date` paragraphs are what the chapter's `index.html` and the settled DOM hold now, `"found": 6, "floor": 4` in `out/shots-arm-a/report.json`. The two years the round's own fix marked after that census were therefore the two that could vanish in silence: the check cannot see a loss that stops at the floor. **The floor now reads 6** (`{ sel: '[data-date]', floor: 6, where: 'the six 背景 paragraphs that carry years' }`), the number was raised in `tools/shot.js` by the worker who holds that file, and the header's own census row for ch02 was corrected with it (`[data-date]×6` where it read `×4`), so the defect is closed rather than standing. It is in this entry because it is what the floor's own value has to be measured against, and because a floor is only as good as the count it was taken on: the six were not there when the census was measured, and nothing made the table follow the page.
- What it does not prove: that the marks are the RIGHT ones, or that each surviving mark still paints (that is the attribute half above it). It proves the count no longer falls in silence, and a deliberate removal is a one-line change in the same table.

## shot: the colour-hook check measures the channels its header says it measures (`tools/shot.js`, `auditColourHooks`)

- **The gap, found by review (2026-09-19).** `PAINT` read `color`, the background and the four border colours of the hooked element and of everything inside it, and nothing else — while the rule discovery accepted a rule declaring `fill`, `stroke` or a pseudo-element colour as a colour hook, and the header listed `fill`/`stroke` among the properties that make one. A mark spent through `fill`, `stroke` or `::after` would have been reported as painting nothing while it painted.
- Chosen: **measure them**, not soften the claim. `PAINT` is now `color`, the four border colours, `background-color`, `fill`, `stroke`, read on every node of the hooked subtree and on that node's own `::before` and `::after`; a pseudo-element style the engine will not give up contributes no channel, is counted in `unread`, and the run prints the count, because a channel that stopped being read is the shape of a check that stopped running. Still outside it, and now said so: the other pseudo-elements (`::marker`, `::selection`, `::first-line`, `::placeholder`), a canvas, an SVG `fill`/`stroke` PRESENTATION ATTRIBUTE written in the markup, and `el.style.color = …` set by JavaScript.
- **The instrument first** (`out/gatefix/probe-channels.mjs`, `out/gatefix/probe-channels.txt`): on `tongjian/ch02`, with the hook attribute on and off, a rule declaring only `fill` moves the computed `fill` `rgb(1, 2, 3)` → `rgb(0, 0, 0)`, only `stroke` moves `stroke` `rgb(7, 8, 9)` → `none`, and a rule declaring only `color` on `::after` moves `rgb(4, 5, 6)` → the ink `rgb(29, 26, 23)` — while the host's own `color` does not move at all, which is exactly why the old list read that mark as inert.
- **Two arms, one tree, one injection, only the channel list differing.** A scratch line at the gate's wait point injected three rules shaped like this book's own hooks (`.zj [data-probe="fill"] { fill: rgb(1, 2, 3); }`, `.zj [data-probe="stroke"] { stroke: rgb(7, 8, 9); }`, `.zj [data-probe="pseudo"]::after { content: ""; color: rgb(4, 5, 6); }`) and put the attribute on three paragraphs that carry a year.
  - Arm A, the new list: `ok tongjian/ch02 desktop light …, 32 colour-hook mark(s) painted …` (29 real marks + the 3 injected), exit 0 — `out/gatefix/channels-armA-with-new-PAINT.txt`. The 29 are the page's marks as they stood when the arms were run, chapter 2's `[data-date]` then being 4 rather than the 6 it carries now, which is why the capture's line reads `census date 4/4`.
  - Arm B, `PAINT` temporarily back to the six old properties and `PSEUDO = []`, same command: exit 1, three false failures, one per injected hook — `the colour hook data-probe="fill" on <p in #history> "…" painted nothing …`, and the same for `data-probe="stroke"` and `data-probe="pseudo"` — `out/gatefix/channels-armB-old-PAINT.txt`.
  - Restored: the three hooks are measured as painted and the chapters are clean again.
- What it does not prove: that the colour is the right one or a readable one (`out/colour2/contrast.mjs` measures contrast), that it survives a hover or a pressed state, or that anything JavaScript paints is seen.

## script: the 原文 and its quotations are Traditional, everything else Simplified (`test/lexicon.test.js`)

- **The rule, made and re-made three times in one session (2026-09-18).** The published book set the 原文 in Traditional and the chapters' prose in Traditional too; the owner read it and said *"我是说这本书一律用简体中文"*. The whole book was converted to Simplified with OpenCC's character table; the owner then read **that** and said *"If the original text is in traditional chinese character that is fine. I just need the rest of the textbook and especially the translation to be in simplified chinese."* A rule that reversed twice in one day is exactly what a gate is for: the third reading was already in flight when the second arrived.
- Claim (in the test's own header): outside the regions that are 通鑑's text, no character exists only in the Traditional script; and the regions that are 通鑑's text are the received text — each page's 原文 block equals its corpus entry character for character, and each run marked `lang="zh-Hant"` is a verbatim quotation from that corpus (or one of two lines the 年表 prints from years the corpus does not cover, named in the test). Bound: script, and that a marked quotation is real. It cannot see a character **both** scripts print but use differently — 著 for 着, 沈 for 沉, 干 for 乾 — because those are not on the Traditional-only list; and it cannot see a quotation the book does not mark, because no mechanical rule can tell one from the book's own sentence.
- The character set is `test/fixtures/traditional-only.txt`: 3,222 characters, OpenCC's `TSCharacters.txt` reduced to those whose Simplified form differs, **checked in rather than fetched at test time** — a gate that reaches the network is not a gate. Denominators are asserted: the file list, the number of characters checked, the 原文 blocks and the marked quotations must all be non-zero, and the artifact is rejected if it is small or maps a character to itself.
- Mutation 1, Traditional into the prose: 「晋阳」 → 「晉陽」 in chapter 2's 背景, one word. Failure, exit 1, the seven sibling tests green:
  `AssertionError [ERR_ASSERTION]: 2 Traditional-only character(s) outside the 原文 or a quotation. … tongjian\ch02-zhi-bo-zhi-wang\index.html:562: 「晉」 is Traditional-only (Simplified: 「晋」), outside any 原文 or quotation — a reader sees it in: 「<p>简子又派家臣尹铎去治晉陽。…」` and the same line for 「陽」. Restored byte for byte: sha256 `03A252A5B22394D653837EC48DB3784B5F89EA5F0CDA97A9376BA6D1EB8EAD4C` before and after.
- Mutation 2, Simplified into the 原文: `<tb-char>為</tb-char>` → `<tb-char>为</tb-char>` in chapter 1's only 原文 block. Failure, exit 1, **two** tests red:
  `AssertionError [ERR_ASSERTION]: tongjian\ch01-san-jia-fen-jin\index.html: the printed 原文 is not CORPUS['zj-001-wei-lie-23'] — either the 原文 was converted away from the received text, or it was edited`, and `1 <tb-char> element(s) on a chapter page point at a character with no entry` — the lexicon is keyed by the received form, so the same edit also breaks card routing. Restored byte for byte: sha256 `A0C6E5CDDDF3F22C14E75D0B01B01DFC5C0027FD289AF69CF390FE599C22EE01`.
- Clean run on the same tree afterwards: `script: 18 file(s) scanned, 490369 Simplified-layer character(s) checked, 0 Traditional-only outside the 原文; 8 原文 block(s) and 222 marked quotation(s) compared against the corpus, 6 figure \`quote\` field(s); 3222 characters in test\fixtures\traditional-only.txt`, 8 of 8 tests green.
- **What the first version of this gate got wrong, and why it was replaced rather than loosened.** It claimed *the book is set in Simplified throughout* and would have gone red on the correct book the moment the 原文 was restored — the temptation being to weaken it. The split rule is strictly stronger: it fails on a wrong script in **either** direction, which the blanket rule could not. Its held-out regions are the corpus's own transcription record (`juan`, `section`, `punctuation`, `note` — no page prints it, and it has to be able to quote a witness in the witness's script), JS and HTML comments, the `work` title, `variants`, and the two characters 絺 and 乾.
- What it does not prove: that a gloss, a note or a translation is *right*, or that the 原文 is the best text — `test/corpus.test.js` holds the second, and the independent review in the round's plan holds the first. It also does not prove the `lang="zh-Hant"` runs are read correctly by any particular screen reader; it proves the attribute is on the element.

## browser-quiet: the flags that keep chromium's crash dialog off the desktop (`test/browser-quiet.test.js`)

- **The gap, reported by the owner (2026-09-12).** A modal `chrome-headless-shell.exe - Application Error` window, *"The exception Breakpoint (0x80000003)"*, appeared on the desktop while a gate run was in flight. It is raised by the browser process, so it outlives the gate and blocks the desktop. No gate could see it: it is outside the browser. Full investigation in [defect-register.md](defect-register.md).
- Claim (in the test's own header): the wrapper declares the flags that suppress the dialog, it applies them by appending to a launch's own flags rather than replacing them, and it patches a browser *type* so every `chromium.launch()` in the process is covered. Bound: text and argument handling of one module. It cannot observe a dialog, and it deliberately does not launch a browser.
- Mutation: `--noerrdialogs` deleted from `QUIET_ARGS` in `tools/zj-quiet-browser.cjs`. Failure, **both tests green before the mutation and both red after**:
  - `AssertionError [ERR_ASSERTION]: the wrapper's flags and this test's expectation disagree; change both deliberately and update the defect register entry`
  - and against a launched browser, in the probe: `AssertionError: the browser was started without --noerrdialogs: the dialog can come back`
  Restored, 3 of 3 pass.
- **Three unsound versions were written before a sound one, which is the reason this entry exists.** (1) Reading `tools/zj-quiet-browser.cjs` as a string: passes with the flags in a comment, and passes while the patch fails to apply. (2) Iterating the wrapper's own `QUIET_ARGS`: deleting a flag would pass the one test that launches a browser. (3) The launch assertion living inside `test/`: `npm test`'s FIRST step is the unit suite, chosen because it is the cheapest and needs nothing but Node, and a test that launches a browser makes that step depend on a downloaded chromium and on a session able to open a named pipe. Measured the same day in a session that could not: every such launch dies with `browserType.launch: spawn EPERM`, which reads as a repository defect. The launch assertion now lives in `tools/zj-quiet-browser-probe.js`, which is run deliberately; the unit test checks the flag list, the merge function, and that `patch()` reaches all three browser types through a fake, with no browser.
- Two facts that cost an attempt each, now comments in the files: `Browser.getBrowserCommandLine` needs a **browser-level** CDP session and is unreachable from a page session, and Chromium refuses to answer it unless `--enable-automation` is on its command line.

## pages: a chapter's page id names its book (`test/pages.test.js`)

- **The defect, found by a read-only probe before the second book's first page existed (2026-09-12).** `tools/lib/browser.js` built a chapter's page id from the chapter number alone, so a second book's chapter 1 collided with the first book's. `test/pages.test.js`'s uniqueness assertion would have caught it — but only once the colliding page was on disk, so a correct new chapter would have turned an unrelated gate red and the failure would have read as "the new book broke the page list". `SHOT_PAGES=ch01`, `DEVICE_PAGES=ch01` and `tools/inspect.js --page ch01` were ambiguous in the same way. Detail in [defect-register.md](defect-register.md).
- Claim (in the test's own header): a chapter's page id starts with its book's id and is `<book>/chNN`, a page in `PAGES` carries that id, and that page's path is the chapter's path.
- Mutation: `browser.js` restored to `` id: `ch${m[1]}` ``. Failure:
  `AssertionError [ERR_ASSERTION]: chapter /biology/ch01-what-is-life/ has page id "ch01", which does not name the book "biology"; two books then share an id for the same chapter number`. Restored, 6 of 6 pass.
- **Why the assertion is on the id's shape and not on uniqueness alone.** After the fix, uniqueness follows from construction — the book component is a unique directory name — so a test of uniqueness would agree with the code by definition, and dropping the book component again is exactly what it would not catch. The shape assertion fails on that mutation; measured, above.

## registry: every figure module parses (`test/registry.test.js`)

- **The defect, found 2026-09-12 while mounting a figure on a new book.** Two modules under `src/figures/` could not execute at all, and `npm run unit` reported 117 of 117 passing. A backtick used to quote an identifier inside a CSS template-literal comment closed the template and left the identifier as code: `` `fr` `` in `zj-split.js`, `` `color` `` in `zj-words.js`. A chapter's figure rendered as the frame's error box — `its module did not load (Unexpected identifier 'fr')` — while the unit gate was green.
- Claim (in the test's own header): every module in `src/figures/` parses. Bound: **syntax only.** It says nothing about whether a module mounts, draws, or reports anything — `npm run drive`, `narrow` and `sweep3d` are what answer those. It parses rather than lints on purpose: a rule forbidding backticks in a CSS comment would have caught `fr` and missed `color`, which is the same mistake in a different module with a different identifier.
- Mutation: `` `fr` `` restored in `zj-split.js` line 238's comment. Failure:
  `AssertionError [ERR_ASSERTION]: 1 figure module(s) do not parse, so the frame will show an error box where a figure should be:`. Restored, 3 of 3 pass.
- **Why the checks above it could not see this.** `test/registry.test.js` never imported the modules — its header says so, because they import `three` by a bare specifier Node cannot resolve — so every assertion it made read a module's *text*: does it export `meta`, does it export `mount`, does `meta` name its kind. All three were true in a file that could not run. `node --check` parses without resolving imports, which is what made the check possible at all.

## sitting: a reader can finish a sitting, and the page does not claim more than the record supports (`tools/sitting.js`)
