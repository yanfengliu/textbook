# Two languages — design of record

How the book is read in English and in Simplified Chinese. Companion to [textbook.md](textbook.md), which stays the design of the book itself, and to [adaptive.md](adaptive.md), which stays the design of the study system.

Status: **designed, nothing built**. Decisions marked **[owner]** came from the owner's request.

## What the owner asked for **[owner]**

*"Also the textbook should support english and chinese."*

## The one architectural idea

A book set in Chinese is not the English book with the words swapped. It is the same argument, the same figures and the same objectives, set in a second type system.

Everything that identifies a thing stays English and stays single: objective ids, item ids, section ids, figure ids and kinds, prerequisite edges, the reader's record. Everything a reader reads is authored twice. The line between the two is drawn once, structurally, so that a translator cannot cross it by accident and the checker can prove they did not.

That is the whole design. The rest of this document is where the line falls, what Chinese type needs that Latin type does not, and what proves it.

## Where the translated prose lives

**A sibling authored page per language, in the chapter's own directory.**

```text
biology/ch01-what-is-life/
  index.html          # English prose
  index.zh.html       # Chinese prose: same section ids, same figure ids and kinds, same order
  glossary.js         # the terms, English, and the stable keys
  objectives.js       # the objective graph: ids, prereqs, teaches, level — language-neutral
  items.js            # the item bank: ids, objectives, kinds, which option is correct
  zh.js               # every Chinese string this chapter needs, keyed by the ids above
```

The Chinese page is authored HTML, the same way the English page is. It is a document: it deep-links, prints, is found by the browser's own find, and reads in reader mode. The prose is the product, so it is written, not generated.

`zh.js` holds no ids of its own. It is a map from the English files' keys to Chinese strings:

```js
export const ZH = {
  glossary: { homeostasis: { term: '稳态', def: '在外界变化时维持体内某一量的稳定……' } },
  objectives: { 'feedback-direction': '预测核心体温偏离设定点时哪个效应器启动，以及响应把温度推向哪边。' },
  items: {
    'i-feedback-direction-1': {
      question: '……',
      options: ['……', '……', '……', '……'],   // positional: `correct` stays in items.js
      whys: [null, '……', '……', '……'],
      explain: '……',
    },
  },
};
```

Because the Chinese file can only name keys the English file already declared, **an identifier cannot be translated**. That is the strongest available form of the rule, and it is why the data files are not duplicated.

### What was weighed against it

| Shape | Why not |
|---|---|
| A `/zh/` mirror of the tree (`biology/zh/ch01-…/`) | Every relative path in the page changes depth, and *every path is relative* is an invariant the site's subpath deployment depends on. `discoverBooks()` and the checker both descend exactly one level below a book, so the mirror is invisible to five gates until they are rewritten. The tree stops matching the URL a reader shares. |
| A sibling book directory (`biology-zh/`) | Free discovery, identical path depth — genuinely the cheapest to wire up. Rejected because it duplicates `objectives.js`, `items.js` and the prerequisite graph. Those are the files where drift is fatal: two copies of an objective id is two mastery records for one claim, and nothing would catch it. Cheap wiring is not worth an unprovable invariant. |
| Runtime substitution from a dictionary | A page that is English in view-source, in find-in-page, in print and to a screen reader until a script has run is not a Chinese book. Whole paragraphs of prose in a JS object cannot be edited as prose or reviewed as prose, and the substitution would have to rewrite HTML with `<tb-term>`, `<tb-check>` and `<tb-sort>` woven through it. |
| Both languages in one file, hidden by `[lang]` | Doubles the bytes of every chapter for every reader, and the browser's own find still finds the hidden half. |

### The cost, stated

Two authored files per chapter drift. Nothing prevents a paragraph being edited in English and not in Chinese, and no checker can read meaning. What the checker *can* prove is that the two pages still have the same skeleton — the same section ids in the same order, the same figures in the same order, the same terms, the same questions against the same objectives. Structural drift is the kind that silently breaks the study system, and that is the kind that gets gated. Meaning drift is caught by a person reading both, and the plan says who.

## Strings in code

A chapter's prose is the bulk of the translation, but it is not all of it. Counted across the tree as it stands:

| Where | Reader-visible English strings |

| `src/components/*.js` | ~169 (`mastery.js` 113, `task.js` 36, the rest 20) |
| `src/palette.js` | 34 (`ORGANELLES` `name` and `role`, `BASES` `name`) |
| `src/shell.js` | 9 |
| `index.html`, `biology/index.html`, `today/index.html` | ~71 |
| `src/styles/*.css` `content:` | 4 |
| `src/learning/store.js` | ~13 (the `why` sentences the queue shows) |

### One lookup, passed in, never imported

`src/strings.js` is the whole machinery:

```js
export function lang() { … }         // from <html lang>, nothing else
export function t(key, vars) { … }   // 'check.verdict.right' -> the current language's string
export function n(value, unit) { … } // a number and its unit, formatted for the language
```

It loads `src/strings/en.js` or `src/strings/zh.js` — one file per language, flat keys. English moves out of the components into `en.js`, which is a gain on its own: 113 strings scattered through `mastery.js` cannot be reviewed, and 113 strings in a file can.

### How a figure gets its strings without importing anything

A figure module declares its own English beside the code that uses it, in `meta`:

```js
export const meta = {
  kind: 'homeostasis',
  title: 'Holding a body temperature',
  strings: { pause: 'Pause', coldPlunge: 'Cold plunge', axisCore: 'Core temperature, °C', … },
};
export function mount(root, ctx) {
  ctx.t('pause');   // 'Pause' or '暂停'
}
```

The frame (`src/components/figure.js`) builds `ctx.t` from `meta.strings` and the overlay for the current language, and passes it in. **The figure contract gains one optional field on `ctx` and nothing else** — no import, no global, no change to `mount`, `setTime`, `describe`, `setVisible` or `setView`. A figure with no `meta.strings` and no `ctx.t` call keeps working.

The Chinese overlay is one file, `src/figures/strings.zh.js`, keyed `kind.key`. One file of ~800 strings is a translation job; 20 files of 40 strings each is 20 jobs that fall out of step.

### `describe()` stays English, values included

`describe()` is machine-facing. Its field names are asserted on by `tools/drive.js` in 50 places, and so are its **string values** — `d.bond === 'ionic'`, `d.phase === 'ice'`, `d.match === 'benzene'`, `d.foldState === 'folded'`. None of those may ever become Chinese.

Four figures currently return the same string they draw on screen, so translating the label would translate the report:

| Figure | Field | Also drawn |
|---|---|---|
| `polymer.js` | `bondName`, `donates.hydroxylFrom`, `donates.hydrogenFrom` | SVG text at `:570`, `:679`; live region at `:461` |
| `carbonkit.js` | `match`, `isomerOf` | `:889`, `:911-912` |
| `soup.js`, `water3d.js` | `phase` | `soup.js:1336`, raw |
| `foldlab.js` | `foldState` | `:585`, raw into the live region (`:503` already maps it correctly for display) |

Each gets a display map beside the reported value, which is the pattern `foldlab.js:503` and `scale.js` (`id` versus `label`/`name`/`about`) already use. This is a prerequisite for translating anything, and it is worth doing whether or not the Chinese edition ships.

### `palette.js` holds no language

`ORGANELLES` carries `{ id, name, color, role }` and is imported by 2D canvas, SVG and WebGL figures alike. `id` and `color` stay; `name` and `role` move to `en.js` under `organelle.<id>.name` and `.role`, and the figures read them through `ctx.t`. The palette is the colour table and must stay free of words, or every figure that draws a colour drags a language in with it.

### Grammar is not a string

`mastery.js:355` builds plurals and `:363` builds English lists ("a, b and c"). Chinese has neither. These become per-language formatters in `src/strings/<lang>.js`, not translated strings, because a translated plural template is how an interface reads wrong in a way nobody can point at. The same applies to the sentence fragments assembled at `mastery.js:517`, `:523-528`, `:575` and `:1120`.

### CSS `content:`

Four word strings (`"Key idea"`, `"All sorted."`, `"Chapter "`, `"Chapter"`) cannot be reached by JS. They get a second rule under `:root[lang|="zh"]`. Four rules is cheaper than moving four labels into the DOM.

## What is shared and what is not

| Shared, never translated | Authored twice |
|---|---|
| Objective ids, `prereqs`, `teaches`, `level` | Objective `statement` |
| Item ids, `objective`, `kind`, which option is `correct`, `figure`, `expect` | Item `question`, option text, each option's `why`, `explain`, `rubric` |
| Glossary keys (`<tb-term ref>`) | Glossary `term` and `def` |
| Section ids, figure ids, figure kinds | Section headings, prose, captions, `data-alt` |
| `describe()` field names **and their string values** | Figure labels, buttons, axis titles, readouts |
| `ORGANELLES[].id`, `.color`; `BASES[].id` | `.name`, `.role` |
| The reader's record: every event keys on objective id and item id | — |
| Chapter directory names (`ch01-what-is-life`) | — |

The record being shared is the point, not an accident. A reader may read chapter 3 in Chinese and answer its questions in English, and it is one mastery of one claim. That only works because the ids are not translated, and it is the clearest argument for drawing the line where it is drawn.

`tools/check-content.js` already enforces the relationships across these files — terms against the glossary in both directions, `teaches` against the sections and figures that exist, items against objectives, prerequisites across chapters. Those rules are keyed on ids, class names and attributes, and none of them reads visible text except one: the figure-citation rule. That one needs work, and the Gates section says how.

## Chinese typography

This is the part that decides whether the Chinese edition is worth shipping, and the honest finding is the strong one: **the book needs a second type system, not a translated one.** The evidence below was measured in the repository's own headless Chromium against the real chapter with Chinese substituted into it, not reasoned from memory. Every number names how it was taken.

### What the current stylesheet does to Chinese today

Substituting Chinese prose into `biology/ch01-what-is-life/index.html` with nothing else changed:

- **The Han glyphs are drawn by SimSun.** No family in `--font-text` has a single Han glyph, so Chromium falls back to the system default for the locale. Measured with `CSS.getPlatformFontsForNode`: `SimSun`, 110 of 110 Han glyphs. On macOS the same page would be PingFang SC, on Android Noto Sans CJK, on a Windows machine with a different regional setting something else again. **The same page is a different typeface on every reader's machine**, and none of them was chosen.
- **The chapter's opening line renders at 72% size.** `.tb-dropcap::first-line` carries `font-variant-caps: all-small-caps`. Han characters have no case, and Chromium synthesises small caps by scaling: measured with a per-character `Range`, every ideograph on line 1 is **13.78 px wide** against **19.22 px** on line 2. It also inherits `letter-spacing: 0.04em`, so the shrunken line is tracked as well.
- **The drop cap collides with the third line.** `.tb-dropcap::first-letter` floats at `4.6em` with `line-height: 0.72` and negative margins tuned to Fraunces' Latin cap height. An ideograph fills its em box, so its ink runs below the float and through the text.
- **The Chinese em dash is drawn by Newsreader.** U+2014 is in Newsreader's Latin subset, so the Latin face wins it: measured, 2 glyphs to Newsreader, 10 to SimSun. A Chinese em dash must be a full-width line that joins its twin; what renders is two short Latin dashes with a gap, at Latin height.
- **So are the quotation marks and the ellipsis.** U+201C/201D/2018/2019 go to Newsreader (measured, 4 glyphs), so Chinese double quotes render at Latin width. U+2026 renders as Latin baseline dots rather than the centred six-dot pair Chinese uses.
- **Bold on Han is synthetic and smears.** SimSun has no 700, so `<b>` and `font-weight: 600` produce a smeared, stroke-merged blob at body size — looked at at 2× and 3×.
- **Emphasis is a synthesised slant.** There is no italic in any Han face. `<em>` produces a mechanically sheared ideograph, which is wrong in the same way and for the same reason the design doc already records for Fraunces.
- **Numerals sink.** `font-variant-numeric: oldstyle-nums` on `body` puts "1.1" at x-height beside characters that fill the em box, so the figure numbers in the prose read smaller than the text around them.

The screenshots behind each of these are listed in the work plan.

### The Chinese type system

| Role | Family | Fallback chain | Why |
|---|---|---|---|
| Han text: body, captions, glossary | **Noto Serif SC** (Google Fonts, variable 200–900) | `"Source Han Serif SC", "Noto Serif CJK SC", "Songti SC", SimSun, serif` | The only book-quality Song with a real weight axis served from the CDN the site already uses. Its Latin is Source Serif-derived and sits on the Han baseline. |
| Han display: titles, section headings | **Noto Serif SC at 600–700** | as above | There is no optical-size Han serif to be had. The English book gets display from a second family; the Chinese book gets it from weight and tracking, which is what Chinese display type actually does. |
| Han interface: figure labels, controls, rubrics, tables | **Noto Sans SC** (variable 100–900) | `"Source Han Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif` | A Song at 11 px loses its horizontals on screen. Chinese interface text is Hei, without exception. |
| Latin inside Chinese, upright | **Noto Serif SC's own Latin** | — | Units, numerals, `pH`, `DNA`, `ATP`. Drawn by the Han face they share a baseline, a weight and a colour. Drawn by Newsreader they do not. |
| Latin inside Chinese, italic | **Newsreader italic** | `"Iowan Old Style", Georgia, serif` | Species binomials and gene names. Noto Serif SC has no italic, and a synthesised one is the defect this repository has already fixed once. `i, em[lang], cite, var` in Chinese prose are set in Newsreader explicitly. |

The Han family is listed **before** the Latin family in the Chinese stack, which is the whole trick: it hands U+2014, U+2018–201D, U+2026 and U+00B7 to the face that draws them full-width, and hands the Latin letters to Noto Serif SC's Latin, which is a deliberate choice rather than a collision. Verified by rendering the same string under both orders and reading back the physical fonts per glyph.

The one thing this costs is the true italic, and it is bought back by naming the Latin face on the elements that need it. That is a rule an author can follow and a checker can enforce.

### The numbers

**Body.** 1.2 rem (19.2 px) — the same step as English, unchanged, because a full-width ideograph at 19.2 px already reads larger than Newsreader at 19.2 px, and the step below (1 rem) is too small for Chinese prose on a desktop. The modular scale stays intact.

**Leading.** `--leading-han: 1.8`, against the English 1.55. Looked at at 1.55, 1.75 and 1.90 at 2×: 1.55 sets a dense grey slab with no room between lines; 1.75 reads; 1.90 is airy. 1.8 sits where Chinese book practice puts it (行距 roughly 0.8 em of extra space) and leaves room for the emphasis dots described below. This is the single change with the largest effect on how the page reads.

**Measure.** Unchanged in the first stage here, and the 36 it used to carry was a slot count rather than a Han count: `--measure: 43.6rem` at 19.2 px is 36 slots of type, and `out/remeasure/probe-cap-control.mjs` measures that line at 1920 px as **32 Han characters on chapter 1 and 31 on chapters 2 and 3** (the `--prose-measure: 43.6rem` arm, injected on the served page), which is inside the comfortable 28–36 band rather than at the top of it, and reads acceptably at 1.8 leading — looked at at 30, 34 and 36 characters. It is left alone here because `tools/devices.js` requires `.tb-text > section > p|ul|h2|tb-key` and `.tb-opener > h1` to share one left and one right edge exactly, and in this edition's shared sheet the measure is entangled with `--text-width`, the spread and `--wide-width: 1100px`. If a typographer looking at the finished page wants a shorter line, the change is still `--text-width` and `--wide-width` together as per-language tokens, and that gate is what proves it was done consistently. The book already set in Han does not take that route: 資治通鑑 runs a ladder of `@media` rungs for the reading column and caps the *prose* line with `--prose-measure: 50rem`, both in §6b of `tongjian/zj.css`, which leaves the column and the 原文/譯文 pair untouched — `out/remeasure/probe-prose-han.mjs` measures it as **36 Han characters a line on chapter 1 and 35 on chapters 2 and 3, with the worst line 38, identical at 1280, 1440, 1600, 1920 and 2560 px**, with the column and the pair at 848 / 838.4 / 998.4 / 1014.4 px. On a phone the column holds about 19 characters, which is right.

**Weight.** Body 400, bold 700, both drawn from the variable font. A synthesised Han bold does not ship. `document.fonts.check()` counts a synthesised face as available and cannot be used to prove this; `CSS.getPlatformFontsForNode` reports the real PostScript name and can.

**Title.** A Song at weight 400 at `--text-6xl` (68.8 px) is too light to open a chapter — its strokes are thin relative to the em where Fraunces' are not. Looked at at 400, 300, 600 and Noto Sans SC 500: the Chinese title takes **600–700** with `letter-spacing: 0`. The English `letter-spacing: -0.02em` on `h1` and `-0.01em` on headings is zeroed for Han, where negative tracking closes the gaps the characters need.

### Punctuation and mixed runs

**Spacing between Han and Latin.** `text-autospace` reached Baseline in November 2025 and its **initial value is `normal`**, so the browser already inserts the quarter-em between an ideograph and a Latin letter or digit. Verified by rendering `核心体温37°C与血糖5mmol/L` with no authored spaces and with `no-autospace`: the automatic spacing is correct and the manual alternative is not. Therefore **the Chinese prose is authored with no space between Han and Latin**, and `npm run check` gains a rule forbidding one, so the two mechanisms cannot both fire.

**Full-width punctuation.** Written as full-width: `，。、；：？！（）《》「」`. The trailing blank half of a full stop and the leading blank half of an opening bracket are correct Chinese setting and are left alone. `text-spacing-trim: trim-start` closes the hole a bracket leaves after a full stop and is a genuine improvement — verified — but the property has limited availability, so it is set as a progressive enhancement and the page is correct without it.

**Emphasis.** `<em>` in Chinese prose is a **着重号**: `text-emphasis: filled dot` with `text-emphasis-position: under right`, in `--ink`, never a slant. Both properties answer `CSS.supports` true in the gate's Chromium; support elsewhere was not tested here and stage 2 checks it. Rendered side by side against slant, bold and underline: the slant distorts the strokes, the underline reads as a link because links in this book are underlined, bold is the device for a term being defined, and the dot is the one that is both correct and quiet. The dots raise the line box, which is part of why the leading goes to 1.8.

**Numerals.** Lining, proportional in prose and tabular in tables. `oldstyle-nums` is turned off for Han text.

**Line breaking.** `line-break: strict` (verified supported). Chinese breaks between any two characters, but a line may not begin with a closing mark or end with an opening one; Chromium applies the basic rules and `strict` tightens them. `hyphens: auto`, which the stylesheet turns on below 600 px, is turned off for Chinese: it does nothing to Han and hyphenates the embedded species names, which is wrong.

**Rubrics.** `.tb-label`, `th`, `h4` and the figure number carry `text-transform: uppercase` and `letter-spacing: 0.14em`. Uppercase is a no-op for Han and is dropped. The tracking **stays** — 疏排 is exactly the Chinese device for a rubric — but it is set in Noto Sans SC, and the `font-variant-caps` on the opener's first line is removed entirely.

**The drop cap goes.** Chinese books do not sink a first character, the mechanism is broken for ideographs in two independent ways, and the opener already carries its authority in the head rule, the tracked unit line, the folio and the title. This is a deletion, not a substitute.

### What changes in the stylesheets

`src/styles/tokens.css` gains a Chinese block, and nothing in the existing `:root` moves:

```css
:root {
  --font-han-text: "Noto Serif SC", "Source Han Serif SC", "Noto Serif CJK SC", "Songti SC", SimSun, serif;
  --font-han-ui:   "Noto Sans SC", "Source Han Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
  --leading-han: 1.8;
  --track-rubric-han: 0.14em;
}
:root[lang|="zh"] {
  --font-text: var(--font-han-text), "Newsreader", serif;
  --font-display: var(--font-han-text), "Fraunces", serif;
  --font-ui: var(--font-han-ui), "Inter", sans-serif;
  --leading-body: var(--leading-han);
}
```

`src/styles/typography.css` gains a `:root[lang|="zh"]` section that turns off what does not apply — the drop cap, `all-small-caps`, `oldstyle-nums`, `text-transform: uppercase`, negative letter-spacing, `hyphens` — and turns on what does: `line-break: strict`, `text-emphasis` on `em`, the Latin face on `i`/`cite`/`var`, lining numerals, weight 700 for `b`/`strong`, weight 600 on `h1`.

The colour tokens, the spacing unit, the baseline grid, the modular scale, the structural vocabulary of rules and the figure palette are **unchanged**. That is what "a second type system" means here: a second set of type decisions inside one design.

### A third request, on the library page (2026-09-16)

The shelf lists both books, so the library page carries Han in a card whose stack was entirely Latin, and 67 glyphs on the site's front door fell to whatever face the reader's machine happened to have. It is fixed with a `text=` subset of the 57 code points the rendered page actually uses, at 30.5 KB over two files, against 41.7 KB for the wider variable ranges, which buy nothing that page sets.

**A subset link on its own changes nothing, and this is the trap.** A browser only reaches for a family that a `font-family` stack names, and every stack in `src/styles/tokens.css` is Latin. So the page must also redefine the three font tokens in its own `<style>`, appending the SC families after the loaded Latin faces and before every system name. A link without a stack is a request the browser never makes, and the page looks exactly as it did.

The page-local override is deliberate and consistent with this document, which already gives a Chinese page its own token block. It does mean type stacks are defined in two places, so the rule is: `tokens.css` holds the book's stacks, and a page overrides them only to add a script that page alone carries, saying so in a comment.

The subset is a hand-maintained character list, normally the fragile choice, and it is safe only because `npm run shot` now fails any element drawn by a face the page never loaded. Drop a character and the gate goes red instead of the page going quietly wrong.

One caveat for anyone reading the census output: CDP reports the sans face as `Noto Sans SC Thin`, which is the variable font's default-instance name and not the weight being rendered. The tongjian pages have always reported the same.

### The cost of the fonts

Measured, cold cache, one chapter's worth of distinct characters (401 Han in the prose, ~150 in the interface vocabulary), Google Fonts serving 101 unicode-range slices per family:

| | Bytes fetched |
|---|---|
| Noto Serif SC | **1.70 MB** (24 slices, ~70 KB each) |
| Noto Sans SC | **0.63 MB** |
| Fraunces + Newsreader + Inter, as today | 0.30 MB |

Pinning the weight axis (`wght@400;700` rather than `200..900`) changes nothing — Google serves the same slices either way, measured.

This is real and it is the largest single cost of the Chinese edition. What makes it acceptable: the slices are cached across the whole site, `display=swap` means the prose is readable from the first paint, and the site already fetches Three.js from a CDN for the 3D figures. What was considered and rejected: subsetting the fonts ourselves (needs a build step), vendoring them (a binary blob far over the fleet's ceiling), and dropping the Hei family for the interface (a Song at 11 px inside a diagram is not legible). Listing the reader's locally installed Han families *ahead* of the webfont would avoid the download for many readers and was rejected for the reason the whole section exists: it reinstates the fallback lottery, and the point is that everyone sees the page that was designed. The local families stay in the tail, where they cover the swap and the offline case.

## How the reader chooses, and how the choice persists

**The language is in the URL.** `…/ch01-what-is-life/` is English and `…/ch01-what-is-life/index.zh.html` is Chinese. A link someone shares must land in the language it was shared in, so nothing redirects a chapter URL, ever.

**`<html lang="zh-Hans">`** on the Chinese pages. It is what selects the tokens, and it is also what the browser uses for font fallback and line breaking, so it is load-bearing twice.

**The switcher** sits in the header on every page, beside the theme toggle. It links to the same document in the other language with a relative href and carries `location.hash` across, so switching language keeps the reader at the same section. On a chapter with no translation yet it is present and disabled, with the reason on it — not hidden, because a missing control is indistinguishable from a broken one.

**`localStorage['tb-lang']`** records the reader's last explicit choice. It is read in exactly three places: the library page and the book's contents page, to decide which edition's chapter links to render; and `today/`, to decide which language the sitting is in. It never changes what a chapter URL resolves to.

**First visit, nothing stored.** The library and the contents page consult `navigator.languages`; if any tag begins with `zh` they render in Chinese and link to the Chinese chapters. This is a preference, not a redirect: the reader is on the page they asked for, it is simply presented in the language their browser asks for, and using the switcher once pins it.

**`today/` is one page.** The record is keyed by objective id, so the sitting is the same sitting in either language; only the item text changes. A reader who has read the Chinese chapters and prefers to practise in English sets the switcher and gets exactly that.

**Nothing is server-side.** No content negotiation, no `Accept-Language`, no cookie, no account, no redirect — `tools/serve.js` and GitHub Pages both serve files, and `npm run subpath` fails any root-absolute path, which is the failure mode a hand-written language switcher invites.

## Gates

Every claim above ends in a gate. The chain is already about 200 browser page loads; the rule that keeps it from doubling is **structure is proved in both languages, behaviour is proved once, and what only Chinese can break gets its own gate.**

### `npm run check` — the most work, and no browser

- **Discovery.** It walks directories itself and finds one `index.html` per chapter. It gains `index.zh.html`, and every existing rule runs over it unchanged. `tools/lib/browser.js`'s `discoverBooks()` gains the same, and `test/pages.test.js` — which derives the list a second way on purpose — gains it too, so the two cannot drift.
- **The figure-citation rule breaks and must be fixed.** `checkDocument` builds `` new RegExp(`Figure\\s+${chapter}\\.(\\d+)`, 'g') `` and requires every `<tb-figure>` to be named in a `<p>`, `<li>` or `<aside>`. A Chinese chapter writes 图 1.2 — or 图1.2, since `text-autospace` supplies the space — so **every figure on every Chinese page fails**. The token becomes per-language (`Figure` / `图`) with `\s*` rather than `\s+`, chosen from the page's own `lang`.
- **Two length thresholds break.** `data-alt` must be ≥ 40 characters and an objective `statement` ≥ 20. Forty Chinese characters is roughly forty English words. Both become per-script: count a Han character as two.
- **New: the two pages have the same skeleton.** Same `<section id>` list in the same order, same `<tb-figure id kind>` list in the same order, same set of `<tb-term ref>`, same `objective` on every `<tb-check>` and `<tb-sort>`. This is the rule that catches the drift a duplicated chapter invites.
- **New: the string overlay is complete.** Every key in `zh.js` resolves to something the English files declare; every glossary entry, objective statement, item question, option, `why`, `explain` and rubric has a Chinese counterpart or an explicit `untranslated` marker with a reason.
- **New: no authored space between a Han character and a Latin letter or digit**, because `text-autospace` supplies it.
- **Bound:** it reads authored HTML with a tolerant tokenizer, not the DOM. It knows nothing about pixels, nothing about meaning, and nothing about whether a translation is *right* — only that it exists and that its skeleton matches.

### `npm run shot` — both languages, full matrix

6 pages become 11 (library, book, three chapters × two languages, today). 3 viewports × 2 themes takes it from 36 loads to 66. It is the cheapest of the browser gates and the one that catches a missing font, a console error and horizontal overflow, which is the failure mode Chinese most invites: an unbreakable Latin run inside Han has no space to break at. `SHOT_LANGS` trims it, and a trimmed run proves only its part.

### `npm run han` — new, and the one that proves the typography

Chinese pages only, 390 px and 1440 px, both themes — 12 loads. It asserts, per page:

1. **Every Han glyph is drawn by the intended family**, read back through `CSS.getPlatformFontsForNode` rather than `document.fonts.check()`, which counts a synthesised face as available. This catches the webfont failing to load, the fallback lottery, and a family name typo — all of which render as a page that looks fine to a gate measuring pixels.
2. **No synthesised weight.** A `<b>`, `<strong>` or `h1` in Han resolves to a PostScript name carrying a real weight.
3. **No line begins with a closing mark and none ends with an opening one**, walked per character with a `Range` and grouped by line box — the same instrument that measured the small-caps shrink.
4. **No last line holds a single Han character** (孤字), by the same walk.
5. **The measure is 28–38 Han characters at 1440 px and 16–24 at 390 px.**
6. **`--leading-body` resolves to the Chinese value**, so a stylesheet regression that drops the `[lang|="zh"]` block is red rather than merely ugly.

**Bound:** it proves the Chinese page is set with the faces and the rules this document specifies. It cannot tell you a translation is good, a heading is well broken, or a page is beautiful. The screenshots it writes to `out/han/` at 3× are for a person to look at, and the work folder's plan says who looked.

### `npm run devices` — both languages, width extremes only

Nine devices × 11 pages is 99 loads on the slowest gate in the chain, and the language does not change which device a reader has; it changes how text fills a width. So the Chinese pages run on `phone-small`, `tablet` and `desktop-wide` — the narrowest, the middle and the widest — and the English pages keep the full nine. 54 loads become 63. `DEVICE_LANGS` trims it. The one-edge rule needs no change as long as the measure stays a fixed length rather than `ch`, which it already is.

### `npm run subpath` — both languages

Discovery brings the Chinese pages in for free once `discoverBooks()` knows about them: 28 loads become 44. The rule it exists for — no same-origin request outside `/textbook/` — is exactly what a language switcher written with an absolute href trips, so this gate earns its place twice here.

### `npm run drive` and `npm run flow` and `npm run sitting` — fix first, then translate

These are the blockers, and they must be fixed before a single string is translated.

- **`tools/drive.js` addresses 76 controls by their visible English label**, through `h.button(/^Cold plunge/)` and friends. Every one would fail as a three-minute locator timeout. The fix is structural and worth doing anyway: every driven control gains a stable `data-action="cold-plunge"`, and the helper at `:860` becomes one line matching that attribute. The recipes' assertions already read `describe()` and are already language-neutral. After the fix, `drive` runs once, in English, because a figure's mechanism does not have a language.
- **`tools/flow.js` has five string assertions** — `'Not quite'`, `'Right'`, the sort bin label `'Alive'`, `'1 of 9 sorted'` and the glossary term `'Homeostasis'`. Four become attribute assertions (`[data-verdict="wrong"]`, `[data-bin="alive"]`, `[data-sorted="1"]`, `tb-term[ref="homeostasis"]`); the fifth, the verdict word, is imported from `src/strings/<lang>.js` so the gate and the page cannot disagree. `flow` then runs in both languages, 2 loads becoming 4.
- **`tools/sitting.js:122` tests `/^learned well$/i` against the mastery labels.** Translate `LEARNED_WELL_WORD` and this matches nothing, `labelledLearnedWell` is zero, and the overstatement check — the reason the gate exists — **passes without running**. That is the most dangerous line in the chain. It imports the word from `src/strings/<lang>.js`, and the gate additionally fails if the word it imported does not appear anywhere on a page that claims a mastered objective, so "did not run" cannot read as "passed". `sitting` runs in both languages: 4 sittings become 8.
- **`tools/narrow.js`** selects buttons positionally and needs no change, but it gains a language dimension (50 loads to 100) because a translated label in a 390 px control is exactly where a Chinese string overflows.
- **`npm run sweep3d`** is unchanged: it measures the bare canvas with every overlay hidden.

### The chain

Roughly 200 loads become roughly 290, and one new step. `tools/test.js` gains `npm run han` after `npm run narrow`. It goes in the chain rather than beside it, for the reason that file already gives: a gate that has to be remembered is a gate that does not run.

### Proving them red

Each new rule is made to fail before it counts, and the mutation goes in `docs/learning/gate-proofs.md`: a figure cited as 图 1.2 on an English page, a `zh.js` with a key removed, a Chinese page with the `[lang|="zh"]` token block deleted, a `<b>` on a machine with no Han bold, a line starting with a full stop, and — the important one — `sitting` against a Chinese page whose mastery word has been translated but whose gate still holds the English literal.

### What makes chapter 30 cheap

By the end of stage 3 a chapter's Chinese edition is **two files** — `index.zh.html` and `zh.js` — with no code change, no gate change, no registry entry and no stylesheet change. The chapter recipe in [chapter-recipe.md](chapter-recipe.md) gains one step. The figure strings are the shared cost and are paid once in stage 5, not per chapter: a chapter's new figures add their `meta.strings` in English and their keys to `strings.zh.js`, which is the same 20-line job whichever chapter they belong to.

### What is deliberately not done

- **Traditional Chinese.** The design admits a third language without change — `index.zh-Hant.html`, `zh-Hant.js`, another token block — but converting Simplified to Traditional mechanically produces wrong terminology in a science text, so it is a translation, not a conversion, and it is not in scope.
- **Translating the lab.** `lab/` is a developer tool and stays English.
- **Translating `describe()`, ids, or anything in `progress/`.**
- **A language-aware `serve.js`.** No redirects, for the reason the subpath gate exists.

## Decisions and their alternatives

- **A sibling page per language over a mirrored tree or a second book.** Keeps every path at the same depth, keeps the objective graph single, and makes translating an identifier structurally impossible. Costs a second authored file per chapter, which the skeleton rule polices.
- **`ctx.t` over a dictionary import in every figure.** One optional field on `ctx` leaves the figure contract intact; twenty imports would not.
- **English strings in `meta.strings`, translations in one overlay file.** The English stays beside the code that draws it, where an author will keep it true; the Chinese stays in one file, where a translator can finish it.
- **Two Han families over one.** Costs 0.63 MB. A Song face at 11 px inside a diagram is not legible, and that is not a trade to make.
- **Han family first in the stack.** Buys correct full-width punctuation, which is otherwise unreachable without redeclaring another vendor's `@font-face`. Costs the true italic, which is bought back by naming Newsreader on `i`, `cite` and `var`.
- **Leading changed, measure left alone.** The leading is where the reading improves most; the measure is entangled with the spread and the one-edge gate, and it reads: 36 slots of type, 31–32 Han characters a line at 1920 px (`out/remeasure/probe-prose-han.mjs`).
- **The drop cap deleted rather than replaced.** It is broken for ideographs in two ways and Chinese books do not use it.
- **Language in the URL, preference in `localStorage`.** A shared link must carry its language. A stored preference must never change where a link lands.
