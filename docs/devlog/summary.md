# Devlog Summary

- 2026-09-16 — Rare characters in the 通鑑 原文 were drawn by the reader's own machine: the pages' Google Fonts request carries no `text=` parameter, so the two families arrive as `unicode-range` slices and **21 of the 1,937 code points the book uses fall outside every one of them** — 蜹、蠆、藺、鼃、驂、讒 on chapter 2 and fifteen more — which reads as almost right on a machine that has SimSun and as tofu on one that does not, in a book whose text is the point. It was a slicing gap and not a font gap, and the page had loaded the right two families, which is why nobody noticed: **a page can load a face and still not cover a character.** Every `tongjian/` page now loads the same two families a second time with a `text=` list of 18 — the six that failed, 紂 U+7D02, which stands only on a card the census cannot open, and eleven witness forms a card prints — costing **13,236 B** on a page that draws one of them and **0 B** on a page that draws none; 𠆸 U+201B8, 𥳑 U+25CD1 and 𣳘 U+23CD8 are excluded deliberately, since nine families were tested and none draws CJK Extension B. Gate: `npm run shot`'s font census, the check that found it — the four-page run ended `shot: 24 page loads clean`, exit 0, and chapter 2 now reads `1644 glyph(s) over 1644 code point(s) in 14 stack(s): Noto Serif SC ExtraLight:1438 Noto Sans SC Thin:206`.
