# Gates (textbook)

What each step of `npm test` proves, where its bound is, how it is trimmed and what was measured, plus the audit gate, the external-request cache and the instruments that are not gates. Until 2026-09-23 this text was the body of the Gates section in [AGENTS.md](../../AGENTS.md); it moved here word for word under the owner's direction that `AGENTS.md` holds rules ([local-rules.md](local-rules.md#the-usage-allowance-is-the-budget-the-owners-direction-of-2026-09-23), point 9). `AGENTS.md` keeps the short list: the pins, the commit gate, the thirteen steps in order, the trims, the audit gate, the red proofs and the instruments. Read the entry for the gate you are about to change or rely on, not the whole file. Where an entry here and the gate's own file header disagree, the header is the closer to the truth, because whoever last changed the gate edited it; measure, then fix whichever is wrong ([local-rules.md](local-rules.md#retest-an-inherited-blocker-before-repeating-it-and-check-what-the-repo-says-about-it)).

- **Node 24**, pinned by `.nvmrc` and `engines.node`; run against v24.18.1. A version mismatch is not a code failure, so check it before reading a red gate as one. Playwright's chromium must be installed once (`npx playwright install chromium`). The gates need the network: every page fetches the fonts from Google Fonts and the 3D figures fetch the pinned Three.js from jsdelivr, and a failed request is a failure.
- **`npm test` is the gate**, and it passes before any commit that touches code. `tools/test.js` runs thirteen steps as separate processes, cheapest first, with no pipe anywhere, and stops at the first red one, naming it: `npm run unit`, `npm run check`, `npm run theme`, `npm run shot`, `npm run flow`, `npm run drive`, `npm run pinned`, `npm run sitting`, `npm run narrow`, `npm run legible`, `npm run devices`, `npm run sweep3d`, `npm run subpath`. Each is also runnable alone, and each states its own bound in its file header. A trimming variable (`THEME_PAGES`, `SHOT_PAGES`, `SHOT_VIEWPORTS`, `SHOT_THEMES`, `DEVICE_PAGES`, `DEVICE_ONLY`, `DEVICE_ENGINES`, `DEVICE_THEMES`, `DRIVE_KINDS`, `PINNED_KINDS`, `NARROW_KINDS`, `NARROW_THEMES`, `LEGIBLE_KINDS`, `LEGIBLE_THEMES`, `SWEEP_KINDS`, `SITTING_THEMES`, `SUBPATH_PAGES`) that names nothing that exists stops the gate naming the valid values (`tools/lib/trim.js`), rather than running nothing and passing; page ids are book-qualified (`biology/ch01`, not `ch01`).
- **`npm run unit`** (`node --test "test/*.test.js"`) covers the content checker on fixtures, the palette's two copies staying equal, the one element table (`src/figures/lib/chem-atoms.js`) against the CSS colours `lib/mol-draw.js` derives from it and against the chapter-2 brief, the registry against the modules on disk, the page list against the chapters on disk, what the Pages trim would leave a reader able to fetch (`test/publish.test.js`: no Markdown survives, a brief in a chapter that does not exist yet is already excluded, the site itself survives, and both consumers still go through the one matcher), every figure module read as text for a binding used before its own `let` or `const` and for a name nothing in the module declares (`test/use-before-declared.test.js`: `if (x)` on a binding declared below it throws rather than skipping, and `x?.set()` hides it better — it sees no closure and nothing dynamic, and says so), the scheduler and the progress store, that no multiple-choice question, in Today or in a chapter's checks, gives its answer away by where it stands, while an answer in Today still records the option's own authored letter (`test/choice-order.test.js`: a chi-square bound over every bank and every check on disk, driven through the two components' own render and answer paths; a check's order must also be the same at the root and under `/textbook/`, and one id on two pages must draw two orders), and the homeostasis model's recovery and drift. The glob is deliberate: `node --test test/` on Node 24 reads no test file at all — it makes one bogus test named `test` and fails it with `ERR_UNSUPPORTED_DIR_IMPORT`, so a run that touched none of the suite still prints a test count (measured on 24.18.1, 2026-09-16). How many tests there are is not written here: the number has been wrong twice, and the claim that matters is that every file matching the glob runs.
- **`npm run check`** reads every page's authored HTML and the data beside it. The prose: registered kinds, unique ids, captions and alts on every figure, every term in the glossary, every entry used and no markup in an entry's term (a term is set as text, so a tag in it is printed), one correct answer per check, bins and reasons on every sort item, heading order, every figure cited in the prose, resolvable hrefs, no TODO. The study data (`objectives.js`, `items.js`): every question names an objective the chapter declares, every prerequisite resolves, the prerequisite graph has no cycle, every objective is taught by a section and figure that exist, a chapter that declares objectives has an item bank at all and at least three items test each objective, every distractor carries the misconception it encodes, and every figure task names something that can grade it. It also runs every figure task's `expect` through the grader's own parser (`expectProblems` in `src/components/task.js`) and fails a clause no figure state could satisfy, and it fails when a chapter has an `items.js` that `today/index.html` lists no `tb-source` for. It fails a check's explanation or option, or a multiple-choice item's explanation, option or why, that names an option by where it is written ("the last option", "option B", 「前两个选项」), because every reader sees the options in a drawn order; the phrasings it knows are listed in `OPTION_POSITION`, and "the last is wrong" is not among them.
- **`npm run theme`** loads every published page that loads the shell, found by following each page's scripts and their imports to `src/shell.js` (`tools/lib/shell-pages.js`, so `lab/` is in and a new page is found without anyone listing it), in seven situations: a stored theme opposite to the emulated system preference, each way round; `?theme=` opposite to it, each way round; nothing chosen; and `localStorage` refusing a read, or refusing access at all. It fails when `data-theme` on `<html>` is not the theme the page is to be drawn in at any moment from `<body>` being inserted to the handshake, or is not the value the shell leaves there — read from the order of the records a MutationObserver installed by an init script collects, so no timing enters the verdict — when a load stores `?theme=` or changes the stored choice, and when the page, storage throwing or not, does not reach the handshake showing its content with no error. It exists because `src/shell.js` applied the reader's theme only after the page had been styled once, so a reader whose stored choice differed from their system saw the whole page in the other theme for one to three frames and then its titles fade across (`docs/learning/defect-register.md`, 2026-09-22). The fix is `THEME_BLOCK` in `src/theme-early.js`, a classic script every such page carries in its `<head>` before its first stylesheet, and `test/theme-early.test.js` in `npm run unit` holds each page's copy as text: it fails a page missing the block, carrying a drifted copy, or carrying it after a stylesheet, and prints the block to paste. Bound: Chromium only, one viewport, and the attribute rather than the pixels, so a block moved to the end of `<head>` still sets it before `<body>` and passes here (the unit test fails it), and a flash in the right theme, a late stylesheet or font, is not seen. `THEME_PAGES` trims it.
- **`npm run shot`** loads every page at 390, 1024 and 1440 px in both themes with `?eager=1&t=0`, fails on any console error, page error, failed request, figure in `error`, or horizontal overflow, and, on a page whose `lang` is English or Chinese, on a figure caption or `aria-label` whose word is not in the page's script (`Figure`, `图`, `圖`), and writes `out/shots/`. Before the shutter opens it waits, one animation frame at a time, for every CSS transition, CSS animation and Web Animation on the page to finish, and fails a page still moving 120 frames after its audits, naming what moves. It also reads back every geometric attribute the mounted figures wrote into the settled DOM and fails one that is negative where SVG forbids it or is not a finite number, naming the kind, the element and the attribute: the console-error check above it catches only what the browser complains about, and `stroke-width="NaN"` is dropped in silence, so the two halves of that class needed two checks. It fails a reader component's text box that is narrower than its own longest word, a sort name that wraps in less than 15 em a line, and a sort whose rows split between two layouts (the text-box block in `tools/shot.js` names the subjects; it presses nothing, so a popover is outside it). It also takes a font census per page load: every text node and `::before`/`::after` string is grouped by its computed stack, weight, style and numeric variant, a probe span per group is measured through CDP `CSS.getPlatformFontsForNode`, and a character drawn by a face the page did not load through `@font-face` fails, narrowed down to the code point and named. What counts as chosen is read off each page, so `tongjian/**`'s Noto Serif SC and Noto Sans SC need no entry and a third book's stack will not either. It cannot be asked once for the page — Chromium walks two levels below the node it is given, so `<body>` reported 19 glyphs on a chapter of 1316 text nodes — and it cannot see text drawn into a canvas, a character that appears only after a control is pressed, or `lab/`, which this gate does not visit. The Today frame is a photograph of a booted study page because **the handshake now covers `<tb-sitting>`** (see the invariant below), so this gate inherits the wait and no longer keeps one of its own; what it keeps is the census, which says the three things the handshake cannot — that the page whose subject that is still carries a `<tb-sitting>` at all, since the handshake's term is vacuously true on a page that lost the element; that the shell still exposes `describeSittings()`; and that every sitting reads back booted **after** the handshake resolved, which is what goes red if the term is deleted from `_check()`. Until 2026-09-17 the handshake said nothing about that element, whose boot imports each chapter's `objectives.js` and `items.js` and then fetches its `index.html`, and this gate's Today frame was a coin toss: two runs with nothing between them differed on 3 of 6 frames, 102,349 bytes against 163,667 for the same frame, and the short one showed none of the study surface. Its frames are for a person to look at, and they are **not byte-reproducible**: three full runs of one still tree on 2026-09-23 wrote 61 of 72 frames identically, and the other 11 differ through SVG label advances, `backdrop-filter`, a figure stage's rounded corners and one unexplained 21-pixel speck, which `tools/shot.js`'s header measures one by one. A hash or a byte comparison of `out/shots/` is not a regression signal. `SHOT_PAGES`, `SHOT_VIEWPORTS`, `SHOT_THEMES` trim it.
- **`npm run flow`** drives the reader controls on the chapter through real mouse, keyboard and drag input: the checks, the sort, a glossary popover, the theme toggle, the phone contents drawer. It presses a check's option by `data-correct`, never by its place, because the order is drawn; so a check that marks the wrong option correct passes it, and `npm run unit` is what sees that. Its screenshots are taken the instant after a press, while an answered option's tint is still in its CSS transition.
- **`npm run drive`** drives every figure's own controls in the lab the same way, one recipe per kind in `tools/drive.js`, asserting what `describe()` reports afterwards; a kind with no recipe fails, and so does a kind whose `describe()` uses one of the four names the frame owns (`id`, `kind`, `number`, `state`), or one the frame holds no handle for or whose handle has no `describe()`. `DRIVE_KINDS` trims it. **A recipe waits by polling, never by sleeping** (`docs/policies/local-rules.md`, "A wait in a gate must poll the artefact, never the wall clock"): `until` polls `describe()`, `atValue` waits for a control to carry the value the figure has already published, `atLeast` waits for the DOM the assertion is about to count, and `stable` waits for a figure to stop moving. A fixed sleep survives only where the elapsed time IS the measurement — where the step's claim is that something did *not* happen while time passed — or where it is letting an animation settle before the step's `out/drive/` screenshot; each of those is commented where it stands, and the file header lists them.
- **`npm run pinned`** is `drive`'s pair from the opposite side: it opens the lab at `?t=0`, works every control every figure has — every visible button, every slider driven by End, Home and PageUp on the control itself, every focusable sent the named keys and the ones its own label documents — and fails a figure still changing across an untouched window of animation frames afterwards. It is what `npm run shot` rests on, since shot photographs every page pinned and presses nothing. One action per fresh mount, deliberately: the first version pressed a kind's controls in order on one page and reported green over the very defect it was written for. It **runs as shards** — `PINNED_SHARDS` processes of the same file, eight by default, each given its slice through `PINNED_KINDS` — because the kinds are independent and because this gate counts animation frames rather than milliseconds, so a loaded machine cannot change a verdict. One command, one verdict: any shard that exits non-zero, dies on a signal, or exits 0 without printing its totals record fails the run, and the summary sums the shards so a reader sees the same counts a single process printed. `PINNED_SHARDS=1` is the reference run. Measured 2026-09-17 on 32 logical CPUs, three arms on a tree hashed still: 410 s at 1, 80 s at 8, 73 s at 16, with kinds, mounts, presses and keys identical in all three (`docs/learning/gate-proofs.md`). 8 is past the knee, not a ceiling.
- **`npm run sweep3d`** renders each WebGL figure at fourteen light views and one dark view through `setView` and fails a frame that is near-black, flat or blank; `out/sweep/` is for a person to look at, because the gate detects an absent frame, not a wrong one. It measures the bare canvas with every HTML overlay hidden: measuring the whole stage passed a figure whose renderer had been replaced by a clear, because the labels and buttons varied enough to look like a frame.
- **`npm run narrow`** mounts every figure at a 390 px stage in both themes and fails one that does not reach ready, draws a blank, flat or near-black frame, or has no control left to press. It then **opens what a reader can open** and measures the opening state and every state a press reaches: the toolbar may not take more than 55% of the stage's height, and on a figure built on `src/figures/lib/bench.js` no pane's drawing may land on another pane's drawing or on a control. A disclosure cannot be read off the markup — the bench has no disclosure primitive and `enzyme-kinetics` builds its two out of `b.toggle` plus `style.display` — so one is found by trying: every visible enabled `button` in the figure's `.fig-toolbar` that carries `aria-pressed`, pressed once in DOM order, pressed again if the press hid controls, the toolbar re-read each round. That was added on 2026-09-17, after a worker found `enzyme-kinetics` at 390 px with a ten-row 320 px toolbar over a 456 px stage and its graph drawn over its readout — two presses from the opening state this gate was the only one measuring, which is the "fixture that ends early" shape. Bounds, printed on every run: an action button is never pressed, so a disclosure with no `aria-pressed` and all its crowding is invisible (**demonstrated**, not asserted, in `docs/learning/gate-proofs.md`); the search is greedy, not exhaustive, so a state needing two presses in the other order is not visited; the two collision checks read only the 9 bench kinds of 44, because a pane grid with the toolbar's measured height as its bottom padding is a promise only the bench makes and for the other 35 a toolbar over the artwork is the design; and a drawing that runs off the stage is clipped by `overflow: hidden` rather than landing on anything, so it is invisible here too (**also demonstrated**). Five figures carry a second composition for a narrow stage, and before this gate none of that code was covered by anything. It writes `out/narrow/` at three times scale, because legibility is the reason those layouts exist and no measure judges it, plus `-opened.png` for the widest state each sweep reached and `-crowd.png` for the state that failed. `NARROW_KINDS` and `NARROW_THEMES` trim it.
- **`npm run legible`** measures the contrast of every glyph a figure puts in the DOM against the pixels actually under it, in both themes, at a 1000x640 stage, in the figure's opening state and after each of its own visible enabled buttons has been pressed once. WCAG 2.x AA — 4.5:1, or 3:1 where the glyph is RENDERED at 24 px or more, which is not the declared size: a `font-size: 40px` letter inside one of `levels`'s thumbnails is six device pixels on screen. It exists because the fills in `src/palette.js` and `src/figures/lib/cell3-colours.js` do not move with the theme while `ink` and `paper` do, so type over one of them is right in one theme and unreadable in the other, and blankness — which is what `npm run narrow` and `npm run sweep3d` measure — is exactly what pale type on a pale fill passes. Each state is rendered three times, as it is, with every measured glyph transparent, and with every measured glyph magenta: the magenta frame is the glyph mask, because a mask read off the figure's own frame would be circular — text the same colour as the fill under it changes no pixel, and the defect would read as "this text draws nothing". Bound: one stage size, so the narrow compositions are `npm run narrow`'s; the opening state plus one press per button, so a pair only a slider or a click on the drawing reaches is not seen; only text in the DOM, so a glyph painted into a canvas or by WebGL is invisible and the canvas count is printed per figure; the surface is the WORST pixel under a glyph's core — every core pixel is given its own ratio and the glyph's is the one at least 95% of them beat, so the reported number is a real surface rather than a named one, and a gradient, a texture and a label straddling two fills are all in range. The 5% set aside is where a hairline rule crossing a stem lives; antialiasing cannot get into it, because a blended pixel's ratio lies between those of the two surfaces it blends. Until 2026-09-17 the rule was a dominant colour under at least 40% of the core pixels, and 44 of `bondlab`'s 48 element symbols were skipped as "varied ground" while the gate reported one problem for a figure whose every O, N and S was below the bar — every line now prints how many of its runs stand on ground that old rule could not have named. A disabled control is exempt, as WCAG 1.4.3 exempts it; and a state that will not hold still is named as NOT measured, with a kind that has no measured state at all failing the run. `ALLOWED` in the file is the list of pairs the book has looked at and not yet decided — every entry carries the ratio it was measured at and stops applying if the pair gets worse, every one spent is printed on green runs too, and an entry nothing spends fails a full run. `DEFERRED` is the list of whole figures it does not visit yet — the second book's three, with the count measured on the day the gate was written and the reason — printed in full on every run and failing the run if a name there is no longer a registered kind. Chapter 4's eight came off it on 2026-09-23: the first run over them found 30 pairs under AA in four figures, and they were fixed with no `ALLOWED` entry. `LEGIBLE_KINDS` and `LEGIBLE_THEMES` trim it.
- **`npm run devices`** emulates nine real devices — small phone, phone, Android phone, phone landscape, tablet in both orientations, small laptop, desktop and wide desktop — with touch where the device has touch and a mouse where it does not, and presses the controls it checks — the contents button, one link in the drawer, every glossary term, a tap outside the drawer — with the input that device actually has; it presses no check option, sort control or figure control. It checks sideways scroll, the header controls being on screen and at least 24 px and truly in the corner, the contents drawer's scrim, scroll lock, focus, outside-tap and link dismissal, **every** glossary popover staying on screen, and the text column and the wide figures each keeping to one pair of edges. A suite that finds none of its subject on a page that must have it — the header on every page; the rail, the glossary terms and the text column on a chapter page — fails naming the selector and the page, from a per-page table in the file, rather than skipping. Every other gate here sets a narrow viewport on a desktop browser, which has a mouse, hover and `pointer: fine`; three of the four defects the owner found on a real phone lived in exactly that gap. `DEVICE_PAGES` trims it. Bound: a page is loaded on one device per *shape* it can exercise — the layout band its width falls in, together with the input its controls are pressed with — rather than on all nine, and the run prints the matrix it derived before it loads anything; `DEVICE_ONLY=phone,phone-android,tablet,desktop-wide` puts the old whole-matrix run back. The derived matrix re-runs on WebKit and Firefox for the two shapes either side of the drawer breakpoint over the library and chapter 1, which between them carry everything this gate checks — not Today, whose study surfaces are `npm run sitting`'s and run on Chromium only — and Firefox's phone arm is a narrow touch viewport rather than a device, because Playwright cannot emulate one there. `DEVICE_ENGINES` and `DEVICE_ONLY` trim those. This gate does **not** pass `?eager=1`, so the handshake here is the shell plus the sitting term and not the figures; before that term it raced Today's boot and photographed whatever had finished — three `DEVICE_PAGES=today` runs with nothing between them wrote the tablet-landscape frame at 109,658 bytes once and 193,829 twice, the short one carrying none of the study surface, and the gate called every one of them clean. A handshake that times out now prints the sittings beside the figure states, so a page held by an unbooted sitting says so instead of showing an empty figure list. **Every load but one pins the figure clocks (`t=0`)**, which is 6.6× faster because a Playwright action on a page of nine animating figures waits for the element to hold still across frames; the cost is that animation-induced layout shift is watched at **one device shape, not nine**, and the run's `running:` line says which load that was — the smallest phone on a chapter page — or says that a trimmed run reached none.
- **`npm run sitting`** completes a study sitting on the Today page with the keyboard alone, in both themes at two widths, from a record it clears first. It fails when a question cannot be answered, when an answer records no objective, no format or no chosen option, when a recorded `chose` is not the bank's own letter for the option whose text was on the button pressed (answered by Enter and, every other question, by the letter printed on the option, at a position where the screen's letter and the bank's differ), when the sitting has not reached its end summary within 24 presses (read from `tb-sitting.describe().finished`), when that end summary carries no per-objective label at all, or when a label anywhere on the page claims more than the record supports. That last one is the reason it exists: the page once said "Learned well" after one right answer, while the store said `learnedWell: false`. The word, the label's class and the end summary's class are read from `src/components/mastery.js`'s exports (`LEARNED_WELL_WORD`, `MARK_WORD_CLASS`, `CLOSING_CLASS`), not from literals, so rewording, translating or renaming moves the check instead of emptying it; the "at least one label" claim is made of the end summary alone, because "Where you stand" renders labels before any question is answered; and every line prints how many labels it read, because `0 label(s)` is a run that compared nothing.
- **`npm run subpath`** rebuilds the tree GitHub Pages actually publishes, from the one exclusion list in `tools/pages-exclude.txt`, serves it under `/textbook/` and loads every page there at two widths in both themes. It fails on a root-absolute path, a same-origin 4xx, a request that escapes the subpath, a figure that is not ready, or horizontal overflow. The site deploys from `main` on every push, so "it works at the root" is not the claim that matters. The list holds **patterns**, not a roll-call: `**/*.md` is what keeps every chapter's `FIGURES.md` off the live site, because naming them one at a time had already published two and would have published chapter 4's. `tools/pages-exclude.js` is the one matcher — this gate, the Pages workflow (`node tools/pages-exclude.js --print0 | xargs -0 rm -rf`, since neither `rm` nor `xargs` expands a glob) and `test/publish.test.js` all go through it, so the three cannot disagree about what a pattern means. It inherits the handshake's sitting term, so its Today frames are reproducible; before that term three runs of `SUBPATH_PAGES=today` on a tree hashed still wrote `today-desktop-dark.png` at 102,349, 163,667 and 50,734 bytes. `SUBPATH_PAGES` trims the page list, and because a trimmed run is not a site-wide verdict the last line names the pages it judged and the pages it did not.
- **The gates fetch each external URL once a run, not once a page load** (`tools/lib/net-cache.js`, installed inside `openPage`). The fonts from Google and the pinned Three.js from jsdelivr are still fetched over the real network — the first request for each URL in each gate's process — and every later request for the same URL is replayed from that run's memory, keyed by URL *and* user agent so three engines never share one stylesheet. Nothing is written to disk, so a run cannot pass with the CDN down: an unreachable URL still fails the run, on the first load, through the same `requestfailed` path. What it stops proving is that a CDN URL is reachable on *every* page load — about ten proofs a chain instead of three hundred. It is worth 130–250 ms a load and about 50 s of `npm run shot`; `NET_CACHE=0` turns it off, which is how that was measured, and every run prints how many URLs it fetched and how many requests it replayed so a cache that did nothing says so.
- **`npm run audit`** (`npm audit --audit-level=high`) is the dependency-audit gate; re-run it on any dependency change. It sits outside `npm test` because it reaches the registry.
- Not gates: `npm run perf` (frame time and draw calls on the machine it runs on), `npm run figure -- <kind>` (one pinned frame of one figure), `npm run inspect <page>` (viewport frames at named elements), `npm run review` (what the reader's study record says, calling no model), `npm run progress:export` and `npm run progress:import` (the record's backup and the way a sitting read on a phone reaches the agent). These are the instruments; a scratch probe names which of them it stands in for.
- Every gate is proved red before it counts, and the proof is in `docs/learning/gate-proofs.md` — **read that file's index and the one entry it sends you to, never the file**, which is dozens of proofs and runs to hundreds of kilobytes. A green run proves what the header says and nothing past it; the screenshots the gates write are the check for the pixels, and the person who looks at them says so in the work folder's plan.
